# React + Next.js Project Setup

## Summary
How to bootstrap and baseline a production-grade Next.js (App Router, TypeScript) project as of Next.js 16.3: `create-next-app` choices, strict TypeScript, path aliases, ESLint or Biome, environment variables, folder conventions, scripts, and agent-ready docs (`AGENTS.md`). The goal is a repo where the first feature PR does not need to fix tooling.

## Category
Next.js

## Subcategories
Scaffolding, TypeScript configuration, linting and formatting, environment variables, folder structure, package scripts, CI baseline, AI agent setup

## Problem It Solves
New projects often start from stale tutorials: Pages Router templates, `next lint`, `.eslintrc`, loose `tsconfig`, secrets under `NEXT_PUBLIC_`, and no CI type check. These choices spread through the codebase and are expensive to undo. This skill gives a current, opinionated baseline.

## When To Use
- Starting a new Next.js application or internal tool.
- Auditing an existing repo's tooling against Next.js 16 defaults.
- Upgrading from Next.js 14/15 and removing deprecated setup (`next lint`, `middleware.ts` naming, sync `params`).
- Preparing a repo for AI coding agents (bundled docs, `AGENTS.md`).

## When Not To Use
- A pure client-side SPA with no SEO/SSR needs and static hosting only; see [vite-react-spa](../vite-react-spa/Skill.md).
- Monorepo-wide tooling decisions (Turborepo, shared configs); see [monorepo-frontend-architecture](../monorepo-frontend-architecture/Skill.md).
- Deep lint-rule design; see [linting-and-formatting](../linting-and-formatting/Skill.md).

## Core Principles
1. Accept framework defaults unless you have a written reason: TypeScript, App Router, Turbopack, `@/*` alias, Tailwind CSS, ESLint or Biome.
2. TypeScript `strict: true` from day one; loosening later is easy, tightening is not.
3. The build must fail on type errors. Never ship `typescript.ignoreBuildErrors: true` without a separate CI `tsc --noEmit`.
4. Secrets live in server-only env vars. `NEXT_PUBLIC_*` is inlined into the client bundle **at build time**; treat it as public.
5. Lint runs as its own script/CI step. Since Next.js 16, `next build` no longer lints.
6. One folder convention, documented in the README/AGENTS.md, enforced by review.
7. Pin the Node version (`engines` + `.nvmrc`); Next.js 16 needs Node >= 20.9.

## Best Practices
- Scaffold with `npx create-next-app@latest my-app --yes` (defaults: TS, Tailwind, ESLint, App Router, Turbopack, `@/*`, AGENTS.md) or choose "customize" to pick Biome, React Compiler, and `src/`.
- Use `src/` to separate app code from root config files. `.env*` files stay at the **project root**, not in `src/`.
- Enable `typedRoutes: true` in `next.config.ts` so `<Link href>` and `router.push` are checked.
- Add `next-env.d.ts` to `.gitignore` (Next.js 16 guidance); it is regenerated by `next dev`/`build`/`typegen`.
- Add `"typecheck": "next typegen && tsc --noEmit"` so route type helpers (`PageProps`, `LayoutProps`, `RouteContext`) exist before tsc runs in CI.
- Add `server-only` to any module that touches secrets or the database.
- Validate env vars at startup with a schema (Zod/Valibot or `@t3-oss/env-nextjs`) and import the typed `env` object rather than reading `process.env` everywhere.
- Commit `.env.example` with keys but no values; never commit `.env.local`.
- Keep `AGENTS.md` (Next.js manages a marked block; add project rules outside the markers). Agents then read version-matched docs in `node_modules/next/dist/docs/`.
- Use the package manager lockfile consistently; enable Corepack or pin `packageManager` in `package.json`.
- Run `npx next upgrade` regularly; small upgrades beat big ones.

## Implementation Guidance

### Decision table: create-next-app prompts
| Prompt | Recommended | Notes |
|---|---|---|
| TypeScript | Yes | Min TS 5.1; TS 7 works via project-local `tsc` CLI |
| Linter | ESLint (rich plugin ecosystem) or Biome (fast, lint+format in one) | Pick one; do not run both on the same rules |
| React Compiler | Yes for new apps | Removes most manual `useMemo`/`useCallback`; see [react-compiler](../react-compiler/Skill.md) |
| Tailwind CSS | Yes unless a design system dictates otherwise | v4, CSS-first config |
| `src/` directory | Yes | Cleaner root |
| App Router | Yes | Pages Router only for legacy |
| Import alias | `@/*` | Do not invent multiple aliases early |
| AGENTS.md | Yes | Opt out with `--no-agents-md` or `agentRules: false` |

### Recommended tsconfig additions
```jsonc
{
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "noImplicitOverride": true,
    "noFallthroughCasesInSwitch": true,
    "verbatimModuleSyntax": true, // forces `import type`; verify compatibility with your tooling
    "paths": { "@/*": ["./src/*"] }
  },
  "include": ["next-env.d.ts", ".next/types/**/*.ts", "**/*.ts", "**/*.tsx"]
}
```

### next.config.ts baseline
```ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  typedRoutes: true,
  reactCompiler: true, // if selected at scaffold time
  poweredByHeader: false,
  // images.remotePatterns: [...] only for hosts you control/trust
}

export default nextConfig
```

### Scripts
```json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "lint": "eslint",
    "lint:fix": "eslint --fix",
    "typecheck": "next typegen && tsc --noEmit",
    "test": "vitest run",
    "e2e": "playwright test",
    "check": "npm run lint && npm run typecheck && npm run test"
  },
  "engines": { "node": ">=20.9" }
}
```
Biome variant: `"lint": "biome check"`, `"format": "biome format --write"`.

### Migrating from `next lint`
`npx @next/codemod@canary next-lint-to-eslint-cli .` then keep a flat `eslint.config.mjs` extending `eslint-config-next` (core-web-vitals + typescript presets).

### Typed environment module
```ts
// src/env.ts
import 'server-only'
import { z } from 'zod'

const schema = z.object({
  DATABASE_URL: z.string().url(),
  AUTH_SECRET: z.string().min(32),
  NODE_ENV: z.enum(['development', 'test', 'production']),
})

export const env = schema.parse(process.env)
```
Client-safe values get a separate module that reads each `process.env.NEXT_PUBLIC_X` **by literal name** (dynamic lookups like `process.env[key]` are not inlined).

### Env load order (first match wins)
`process.env` > `.env.$(NODE_ENV).local` > `.env.local` (skipped in test) > `.env.$(NODE_ENV)` > `.env`.
Need runtime (not build-time) values in the browser? Read them on the server (after `await connection()`) and pass down as props.

### Folder convention (feature-first)
```
src/
  app/                  # routes only: page, layout, loading, error, route.ts
    (marketing)/        # route groups for layout separation
    (app)/dashboard/
      _components/      # private, route-local components (underscore = not routable)
  components/ui/        # shared primitives (e.g. shadcn/ui)
  features/<feature>/   # components, actions.ts, queries.ts, schemas.ts
  server/               # DAL, db client, auth helpers ('server-only')
  lib/                  # framework-agnostic utilities
  env.ts
proxy.ts                # Next 16 name for middleware (at root or src/)
```

## Recommended Workflow
1. Check Node version (`node -v` >= 20.9) and choose the package manager.
2. Run `create-next-app` with recommended defaults, customizing only linter/compiler/src.
3. Tighten `tsconfig`, add `typedRoutes`, add `typecheck` and `check` scripts.
4. Add `src/env.ts` validation and `.env.example`; confirm `.gitignore` covers `.env*.local` and `next-env.d.ts`.
5. Add the folder skeleton and a short conventions section to `AGENTS.md` (outside the managed block).
6. Add Prettier (if ESLint) or rely on Biome formatting; add an editor config.
7. Add Vitest + Testing Library and Playwright (see testing skills).
8. Wire CI: install with frozen lockfile, `lint`, `typecheck`, `test`, `build`.
9. Commit, then run `next build` locally to confirm there are no warnings about env or config.

## Patterns
- **Route-local private folders**: `_components`, `_lib` inside `app/` segments keep colocated code non-routable.
- **Route groups** `(group)` for different root layouts (marketing vs app) without URL changes.
- **Single typed env gateway**: all server env access via `env.ts`; lint-ban `process.env` elsewhere (`no-restricted-properties`).
- **Server/client module split**: `features/x/queries.ts` (server-only) vs `features/x/hooks.ts` ('use client').
- **AGENTS.md + CLAUDE.md** (`@AGENTS.md`) so every coding agent reads the same rules.

## Anti-Patterns
- **Starting from Create React App or Pages Router templates.** CRA is deprecated; Pages Router misses RSC/Server Actions. Fix: App Router scaffold.
- **Using `next lint` or expecting `next build` to lint.** Removed/changed in 16. Fix: explicit `eslint`/`biome` scripts + CI step.
- **`NEXT_PUBLIC_API_SECRET`.** Inlined into JS shipped to every user. Fix: server-only env, proxy calls through Route Handlers/Server Actions.
- **Building one Docker image for many environments while relying on `NEXT_PUBLIC_*`.** Values are frozen at build. Fix: runtime server read + props, or per-env builds.
- **`ignoreBuildErrors: true` to "unblock" deploys.** Ships type bugs. Fix: fix types; if temporary, CI `tsc --noEmit` must still gate.
- **Deep relative imports `../../../`.** Fix: `@/` alias.
- **Placing `.env` inside `src/`.** Not loaded. Fix: project root.
- **Editing `next-env.d.ts`.** Overwritten. Fix: separate `types/*.d.ts` included in tsconfig.
- **Naming new files `middleware.ts` in Next 16.** Renamed to `proxy.ts`. See [nextjs-middleware-proxy](../nextjs-middleware-proxy/Skill.md).

## Accessibility
- Set `<html lang="...">` in the root layout from the start.
- Include `eslint-plugin-jsx-a11y` rules (bundled in `eslint-config-next`) or Biome's a11y group; do not disable them globally.
- Add `@axe-core/playwright` checks to the e2e baseline; see [automated-accessibility-testing](../automated-accessibility-testing/Skill.md).

## Responsive Design
- Keep the default viewport handling (Next.js injects the viewport meta); customize via the `viewport` export, never with `user-scalable=no`.
- Tailwind v4 breakpoints and container queries are available immediately; agree on a breakpoint scale in the design tokens.

## Performance
- Turbopack is the default for dev and build; only use `--webpack` if a plugin requires it.
- Enable React Compiler for new projects to reduce re-render cost without manual memoization.
- Use `next/font` and `next/image` from the first page; retrofitting is harder.
- Add `@next/bundle-analyzer` (or Turbopack's analyzer) before the bundle grows.

## Security
- Server-only env vars; typed validation; `server-only` imports for DB/secret modules.
- `poweredByHeader: false`; set security headers/CSP early (see [content-security-policy](../content-security-policy/Skill.md)).
- Frozen lockfile installs in CI; enable Dependabot/Renovate; review `postinstall` scripts (see [dependency-supply-chain-security](../dependency-supply-chain-security/Skill.md)).
- Configure `images.remotePatterns` narrowly; avoid wildcard hosts.
- If self-hosting multiple instances, set a stable `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` from your secret manager (never committed).

## Testing
- Vitest + React Testing Library for units/components (async Server Components are better covered by e2e).
- Playwright for e2e against `next build && next start`.
- CI gate order: lint -> typecheck -> unit -> build -> e2e.
- Load env in tests via `@next/env` `loadEnvConfig(process.cwd())`; `.env.test` is committed, `.env.test.local` is not.

## Framework Notes
- **Next.js**: Next 16 made `params`/`searchParams`/`cookies()`/`headers()` async; `middleware.ts` became `proxy.ts`; Cache Components (`cacheComponents: true`, `"use cache"`) is the modern caching model; see [nextjs-caching-and-revalidation](../nextjs-caching-and-revalidation/Skill.md).
- **React (Vite SPA)**: equivalent baseline is `npm create vite@latest -- --template react-ts`; env prefix `VITE_`; see [vite-react-spa](../vite-react-spa/Skill.md).

## AI Agent Guidance
- Do: read `node_modules/next/dist/docs/` (or AGENTS.md pointer) before writing Next.js APIs; your training data may predate Next 16.
- Do: verify Node, Next, React, TypeScript versions from `package.json` before choosing APIs.
- Do: add new env vars to `env.ts` schema and `.env.example` in the same change.
- Don't: create `.eslintrc`, `pages/`, `middleware.ts`, or `next lint` scripts in a Next 16 repo.
- Don't: put any secret in `NEXT_PUBLIC_*`, or print env values in logs.
- Don't: disable strict mode or add `ignoreBuildErrors` to get green.
- Before done: `lint`, `typecheck`, `build` all pass; `git status` shows no committed `.env*.local`; routes render in `next dev` without overlay errors.

## Examples
```tsx
// src/app/(app)/dashboard/[teamId]/page.tsx — typed async params with generated helper
export default async function Page(props: PageProps<'/dashboard/[teamId]'>) {
  const { teamId } = await props.params
  return <h1>Team {teamId}</h1>
}
```

```js
// eslint.config.mjs — restrict raw env access outside env modules
import next from 'eslint-config-next'

export default [
  ...next,
  {
    files: ['src/**/*.{ts,tsx}'],
    ignores: ['src/env.ts', 'src/env.client.ts'],
    rules: {
      'no-restricted-properties': ['error', { object: 'process', property: 'env', message: 'Import from @/env' }],
    },
  },
]
```

```md
<!-- AGENTS.md (below the Next.js managed block) -->
### Project rules
- Server data access only in src/server (import 'server-only').
- Validate all Server Action input with Zod schemas in features/*/schemas.ts.
- Run `npm run check` before declaring a task done.
```
